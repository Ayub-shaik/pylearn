# PyLearn

PyLearn — An Online Python Learning App (Web-First, Account-Based)

Web app (mobile-browser-first) with an AI tutor (text, voice later). Teaches Python via lessons,
interactive checkpoints, adaptive quizzes, and step-by-step hints. Sign in with Google to save
progress across devices; a small self-hosted LLM (no paid cloud AI API) powers hint/quiz
generation behind our backend. Native Play Store app is a separate, later phase — see `sdlc.md`.

Why PyLearn?

Practice-driven: Learn Python by doing—short lessons → guided exercises → immediate feedback.

Adaptive: The tutor detects your mastery and adjusts difficulty, giving targeted hints and explanations.

Account-based: Sign in with Google and your progress follows you across devices; no account is required to try it, but progress then stays local to that browser only.

Self-hosted AI, not a paid API: Hints and quiz variations are generated by a small model we run ourselves — never a third-party paid LLM API.

Two targets, one core: Shared domain logic (`packages/core`) used by both the web app and the backend today, and by a future native mobile app later.

Project Goals

Deliver a web app with lessons, exercises, adaptive quizzes, and progress tracking, usable from any desktop or mobile browser.

Let external users sign up (Google) and keep their progress in sync across devices.

Keep the AI tutor small and self-hosted; fall back to deterministic, curated content whenever the model is unavailable or its output isn't trustworthy.

Provide transparent explanations (why each option is right/wrong).

Make learners feel accompanied: "Okay, let's put you to the test!"

Ship a native Android/iOS app later as its own project, reusing only the shared domain logic and the backend's HTTP API — not a WebView wrapper.

AI Design (small, self-hosted, tiered)

The AI tutor's job is narrow: reword/vary quiz questions and elaborate on authored hints, grounded in
our own curated lesson content — not open-ended code generation. Generation is tiered, cheapest and
most reliable first:

1. Cache — previously generated variants for a checkpoint are served directly, no live inference.
2. Local Ollama (`llama3.2:3b`) — runs on our own infrastructure, concurrency-capped so it never
   blocks on itself.
3. Optional cloud overflow (NVIDIA NIM free tier) — off by default, only for extra headroom.
4. Deterministic template — the lesson's own authored hint/explanation text, used whenever the
   above tiers miss or produce output that doesn't look grounded in the source material.

Checkpoint correctness is always evaluated deterministically (`packages/core`) — the model only
rephrases, it never decides right or wrong.

Speech (future)

ASR (offline): whisper.cpp (tiny/base) or Vosk.

TTS (offline): Piper or Coqui TTS small voices.

Core Features (MVP)

Lesson Flow: Bite-sized text + optional audio narration → code demo → mini challenge.

Teacher Mode: Proactively prompts: "Okay, let's put you to the test."

Guided Exercises: Fill-in-the-blank, multiple choice, and live code cells with instant feedback.

Hints & Explanations:

If wrong: hold the learner, show hints → reveal answer if needed.

For each option: explain why correct and why not with examples.

Adaptive Engine: Scaffolds difficulty from your accuracy/latency; surfaces remedial micro-lessons.

Progress & Scoring: XP, streaks, topic mastery bars, session summaries, and a personal "next steps".

Account-based Data: Signed-in progress lives in Postgres, tied to your Google account; anonymous use falls back to local-only browser storage.

No paid AI APIs: Hints/quiz variations come from our own self-hosted model, with a free-tier cloud option as an optional, off-by-default overflow valve.

Architecture (shared-core first)

Monorepo

pylearn/
apps/
web/ # React + Vite + TS SPA (PWA, offline cache as a convenience layer)
api/ # Fastify + TS backend: accounts, sessions, tiered LLM proxy
android/ # placeholder for a later, separate native mobile phase
packages/
core/ # Domain logic: lesson graph, adaptive engine, scoring, hinting, mastery — shared by web and api
llm/ # Shared LLM types + Ollama-reachability probe
speech/ # ASR/TTS wrappers (future)
ui-kit/ # Reusable UI components (cards, quiz widgets, code runner, progress bars)
data/ # Lesson content, quizzes, explanations (versioned JSON/MD), server-owned source of truth
infra/
nginx/ # Reverse proxy: serves the web static bundle, proxies /api to the api service
docker-compose.yml # web + api + db (Postgres); host Ollama reused as-is, not containerized

Key Patterns

`packages/core` runs identically in the browser and in `apps/api` — no duplicated domain logic between client and server.

nginx proxies `/api` to the backend under the same domain, so auth cookies stay same-origin with no CORS complexity.

LLM routing (`apps/api/src/llm`): cache → local Ollama → optional cloud overflow → deterministic template, always grounded in `packages/data` content.

Guardrails: deterministic templates for hints/explanations by default; retrieve curated snippets from `packages/data` first, then only augment with the LLM, and discard any ungrounded output.

Data Model (conceptual)

User: Google account identity, email, display name/avatar.

Curriculum: tracks → modules → lessons → checkpoints (typed: note, quiz, coding).

Mastery: per-topic mastery %, attempts, last-seen difficulty.

Session: start/end, score deltas, hint usage, stuck points — persisted server-side for signed-in users.

Security & Privacy

No paid AI APIs for the core product.

Signed-in progress is stored server-side (Postgres), tied to your Google account; anonymous use stays local to your browser.

Google sign-in uses a server-side OAuth flow; secrets never reach the browser bundle.
